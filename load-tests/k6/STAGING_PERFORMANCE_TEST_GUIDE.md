# SETU Staging Performance Test Guide

Use this guide to run the same SETU speed tests against a staging backend and produce analysis-ready reports.

## What This Tool Runs

Default staging run:

- `smoke-auth`
- `dashboard`
- `progress-read`
- `planning-read`
- `design-read`

The heavy `mixed-read` scenario is excluded by default because it ramps toward 300 virtual users. Run it only during an approved staging load-test window.

## Prerequisites

- Staging backend must be reachable from this machine.
- Use backend root URL, not frontend URL and not `/api`.
- Staging credentials must be valid.
- IDs must exist in staging:
  - `PROJECT_ID`
  - `COMPANY_ID`
  - `ACTIVITY_ID`
  - `EPS_NODE_ID`

## Recommended Command

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\load-tests\k6\run-staging-performance.ps1 `
  -BaseUrl "https://your-staging-backend.example.com" `
  -Username "admin" `
  -Password "your-password" `
  -ProjectId "2" `
  -CompanyId "1" `
  -ActivityId "1967" `
  -EpsNodeId "410" `
  -SkipPdf
```

## Include Mixed Load Test

Use this only when the staging team is ready for a heavier test.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\load-tests\k6\run-staging-performance.ps1 `
  -BaseUrl "https://your-staging-backend.example.com" `
  -Username "admin" `
  -Password "your-password" `
  -ProjectId "2" `
  -CompanyId "1" `
  -ActivityId "1967" `
  -EpsNodeId "410" `
  -IncludeMixedRead `
  -SkipPdf
```

## Output Files

The tool creates a timestamped folder under:

```text
load-tests/k6/reports/staging-<host>/<timestamp>/
```

Important files:

- `staging-performance-analysis.md`: main analysis file to share.
- `load-test-report.md`: raw k6 report generated by the existing suite.
- `suite-manifest.json`: run metadata and scenario status.
- `*-summary.json`: k6 metrics per scenario.
- `*-stdout.txt` and `*-stderr.txt`: raw scenario logs.

## How To Send For Analysis

After the run finishes, share the full run folder or at least these files:

- `staging-performance-analysis.md`
- `load-test-report.md`
- all `*-summary.json`
- any `*-stderr.txt` files

## What To Watch

- `p95 latency`: should ideally stay below 2 seconds for read flows.
- `http_req_failed`: should stay below 1%.
- `checks`: should stay above 99%.
- `mixed-read`: any timeout here is a capacity warning, not just a script issue.

## Safety Notes

- Do not run against production unless explicitly approved.
- Do not use a frontend URL such as `https://staging.example.com` if the backend is separate.
- Do not include `mixed-read` during business hours unless staging capacity is prepared.
